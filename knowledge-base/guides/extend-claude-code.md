Claude Code משלב מודל שמנתח קוד עם כלים מובנים לפעולות קבצים, חיפוש, הרצה וגישה לרשת. הכלים המובנים מכסים את רוב משימות הקוד. המדריך הזה עוסק בשכבת ההרחבה — הפיצ'רים שמוסיפים כדי להתאים אישית מה קלוד יודע, לחבר אותו לשירותים חיצוניים, ולאוטומט תהליכי עבודה.

## סקירה — מה מחבר לאיזה חלק בלולאה

- **CLAUDE.md** מוסיף הקשר מתמיד שקלוד רואה בכל סשן
- **Skills** מוסיפים ידע לשימוש חוזר ותהליכי עבודה שניתן להפעיל
- **MCP** מחבר קלוד לשירותים ונתונים חיצוניים
- **Subagents** מריצים לולאות עצמאיות בהקשר מבודד ומחזירים סיכומים
- **Agent teams** מתאמים מספר סשנים עצמאיים עם רשימת משימות משותפת
- **Hooks** מריצים סקריפט, בקשת HTTP, פרומפט, או subagent כשClaude Code מגיע לאירוע מחזור חיים
- **Plugins** ו-**Marketplaces** אורזים ומפיצים את כל הפיצ'רים האלה

## השוואת פיצ'רים

| פיצ'ר | מה הוא עושה | מתי להשתמש | דוגמה |
| :--- | :--- | :--- | :--- |
| **CLAUDE.md** | הקשר מתמיד שנטען בכל שיחה | קונבנציות פרויקט, כללי "תמיד תעשה X" | "השתמש ב-pnpm, לא npm. הרץ tests לפני קומיט." |
| **Skill** | הוראות, ידע ותהליכי עבודה | תוכן לשימוש חוזר, משימות חוזרות | `/deploy` מריץ checklist פריסה; docs של API עם דפוסי endpoints |
| **Subagent** | הקשר הרצה מבודד שמחזיר תוצאות מסוכמות | בידוד הקשר, משימות מקביליות, עובדים מתמחים | מחקר שקורא הרבה קבצים אבל מחזיר רק ממצאים מרכזיים |
| **MCP** | חיבור לשירותים חיצוניים | נתונים או פעולות חיצוניות | שאילת מסד נתונים, פרסום ב-Slack, שליטה בדפדפן |
| **Hook** | סקריפט, HTTP, פרומפט, או subagent המופעל על ידי אירועים | אוטומציה שחייבת לרוץ בכל אירוע תואם | הרצת ESLint אחרי כל עריכת קובץ |
| **Artifact** | פרסום פלט סשן כדף אינטראקטיבי | פלט שרוצים לראות או לשתף חזותית | ציר זמן אירוע שמתעדכן בזמן חקירה |

## בניית סביבה בהדרגה

לא צריך להגדיר הכל מראש. כל פיצ'ר מגיע עם טריגר מוכר, ורוב הצוותים מוסיפים אותם בסדר הזה:

| טריגר | מה להוסיף |
| :--- | :--- |
| קלוד טועה בקונבנציה או פקודה פעמיים | הוסף ל-CLAUDE.md |
| אתם כותבים שוב ושוב את אותו פרומפט להתחלת משימה | שמרו כ-skill שניתן להפעיל |
| אתם מדביקים שוב ושוב את אותה הסבר רב-שלבי לשיחה | אבדו אותו כ-skill |
| אתם מעתיקים נתונים מטאב שקלוד לא רואה | חברו את אותה מערכת כ-MCP server |
| קלוד קורא הרבה קבצים כדי למצוא הגדרה | התקינו פלאגין code intelligence לשפה שלכם |
| משימת צד מציפה את השיחה בפלט שלא תצטרכו | הפנו אותה ל-subagent |
| רוצים שמשהו יקרה בכל פעם ללא בקשה | כתבו hook |
| ריפו שני צריך את אותה הגדרה | אבדו אותה כ-plugin |

## השוואות בין פיצ'רים דומים

**Skill לעומת Subagent**

Skills הם תוכן לשימוש חוזר שניתן לטעון לכל הקשר. Subagents הם עובדים מבודדים שרצים בנפרד מהשיחה הראשית שלכם.

- השתמשו ב-**skill** לחומר עיון או תהליכי עבודה שניתן להפעיל
- השתמשו ב-**subagent** כשצריך בידוד הקשר או כשחלון ההקשר מתמלא — המשימה עשויה לקרוא עשרות קבצים, אבל השיחה הראשית מקבלת רק סיכום

**CLAUDE.md לעומת Skill**

CLAUDE.md נטען בכל סשן אוטומטית. Skill נטען לפי דרישה.

- שימו ב-CLAUDE.md מה שקלוד צריך תמיד לדעת: קונבנציות קוד, פקודות build, כללי "לעולם אל"
- שימו ב-skill חומר עיון שנדרש לפעמים (docs של API, style guides) או תהליך עבודה שמופעל עם `/name`
- כלל אצבע: שמרו את CLAUDE.md מתחת ל-200 שורות. אם הוא גדל, העבירו חומר עיון ל-skills

**Hook לעומת Skill**

Hook מריץ תמיד כשהאירוע שלו קורה. Skill מספק הוראות שקלוד מפרש.

- השתמשו ב-**hook** כשהפעולה חייבת לקרות אותו דבר בכל פעם ללא צורך בחשיבה של קלוד: עיצוב בשמירה, דחיית `rm -rf /`, שליחת הודעת Slack
- השתמשו ב-**skill** כשקלוד צריך להחליט איך להחיל את הצעדים, או כשהתוכן הוא ידע ולא סקריפט

גדרו guardrails ב-hooks. הוראה כמו "לעולם אל תערוך `.env`" ב-CLAUDE.md היא בקשה, לא ערובה. hook של `PreToolUse` שחוסם את העריכה הוא אכיפה.

**MCP לעומת Skill**

MCP מחבר קלוד לשירותים חיצוניים. Skills מרחיבים את מה שקלוד יודע, כולל כיצד להשתמש באותם שירותים.

- **MCP** מעניק לקלוד כלים ייעודיים למערכת חיצונית עם החיבור והאימות שמנוהלים על ידי השרת
- **Skill** מעניק לקלוד ידע על כיצד להשתמש בכלים אלה ביעילות
- דוגמה: שרת MCP מחבר קלוד למסד הנתונים שלכם; skill מלמד את קלוד את המודל הנתוני שלכם ודפוסי השאילתות הנפוצים
