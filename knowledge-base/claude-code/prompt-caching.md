Prompt caching מאיץ את Claude Code ומוריד עלויות. בלי מטמון, ה-API היה מעבד מחדש את כל ההיסטוריה שלך בכל תור. עם מטמון, הוא משתמש שוב במה שכבר עיבד, חוייב בתעריף token מטמון מוזל, ומעבד במלואו רק את מה שהשתנה.

## מה זה עושה / למה זה שימושי

Claude Code מנהל prompt caching אוטומטית. בכל זאת, שווה להבין כיצד הוא עובד — כי כמה פעולות מבטלות את המטמון ומאטות את התור הבא ומייקרים אותו בזמן שהמטמון נבנה מחדש.

## כיצד עובד המטמון

בכל פעם שמשלוחים הודעה ב-Claude Code, נשלחת בקשת API חדשה. המודל לא זוכר כלום בין בקשות, ולכן Claude Code שולח מחדש את כל ה-context: system prompt, context הפרויקט, כל ההודעות והתוצאות הקודמות, וההודעה החדשה שלך. תוכן חדש מתווסף בסוף, מה שאומר שרוב כל בקשה זהה לקודמת.

ה-API שומר במטמון על ידי התאמה של תחילת כל בקשה (prefix) לתוכן שעיבד לאחרונה. בתור רגיל, ה-prefix הוא כל הבקשה הקודמת ורק ההחלפה האחרונה חדשה. ההתאמה מדויקת — שינוי בכל מקום ב-prefix מחייב עיבוד מחדש של כל מה שאחריו.

כדי למקסם התאמות prefix, Claude Code מסדר כל בקשה כך שתוכן שמשתנה לעתים רחוקות מגיע קודם:

| שכבה | תוכן | משתנה כאשר |
|:--|:--|:--|
| System prompt | הוראות ליבה, הגדרות כלים, סגנון output | קבוצת הכלים הטעונים משתנה, או Claude Code מתעדכן |
| Project context | CLAUDE.md, זיכרון אוטומטי, חוקים לא-מתוחמים | Session מתחיל, או אחרי `/clear` / `/compact` |
| Conversation | ההודעות שלך, תגובות Claude, תוצאות כלים | כל תור |

שינוי בשכבת ה-conversation משאיר את system prompt ו-project context במטמון. שינוי ב-system prompt מבטל הכל, כי כל תוכן מאוחר יותר יושב מאחורי prefix שונה.

שתי הגדרות אינן חלק מטקסט ה-prompt, אך שתיהן חלק ממפתח המטמון:

- **מודל**: לכל מודל יש מטמון משלו. החלפת מודל מחשבת מחדש את כל הבקשה גם כשהתוכן זהה
- **רמת effort**: לכל רמת effort יש מטמון משלה לאותו מודל. שינוי באמצע session מחשב מחדש את כל הבקשה

## פעולות שמבטלות את המטמון

פעולות אלה גורמות לבקשה הבאה לפספס חלק מהמטמון או את כולו. תראו תור איטי ויקר יותר פעם אחת, ואחריו ה-prefix החדש ייכנס למטמון. רובן הן פעולות שאפשר להימנע מהן באמצע משימה ברגע שיודעים שיש להן עלות.

**החלפת מודל** (`/model`): כל מודל יש לו מטמון משלו. גם כשהתוכן זהה, המטמון חדש.

**שינוי רמת effort** (`/effort`): המטמון מזוהה לפי שילוב מודל+effort. Claude Code מציג dialog לאישור לפני החלת שינוי שיבטל את המטמון.

**הפעלת fast mode**: מוסיף request header שהוא חלק ממפתח המטמון. הפעלה בתחילת session עולה פחות מהפעלה עמוק בתוך session ארוך.

**חיבור או ניתוק שרת MCP**: הגדרות כלים יושבות בשכבת system prompt. ה-impact תלוי בסוג הטעינה:
- **כלים דחויים** (ברירת המחדל): שרת שמתחבר, מתנתק, או משנה את רשימת הכלים שלו רק מוסיף תוכן ולא מפריע לכלום שכבר נשמר במטמון
- **כלים שנטענים ל-prefix**: כל שינוי בהם מבטל את המטמון

**הפעלה או כיבוי plugin**: הגדרות כלים משתנות.

**דחיסת השיחה** (`/compact`): בונה מחדש את ה-prefix — תור איטי אחד, ואחריו המטמון החדש.

**שדרוג Claude Code**: עדכון עשוי לשנות את system prompt.

## ניהול TTL והארכת חיי המטמון

ערכי מטמון פוקעים אחרי תקופת חוסר פעילות. ברירת המחדל היא 15 דקות בשרתי Anthropic. ל-Anthropic API (גרסה 2024-11-01 ומעלה), אפשר לבקש TTL של עד שעה אחת עם explicit cache breakpoints בבקשה עצמה.

Claude Code מנהל זאת אוטומטית. שמירה על session פעיל מרחיבה את חלון ה-caching.

## טיפים לשימור ביצועי מטמון

בחרו מודל ורמת effort בתחילת session, ושמרו `/compact` להפסקות טבעיות בין משימות. ככל שעושים פחות שינויים באמצע משימה, כך שיעור ה-cache hit גבוה יותר.
